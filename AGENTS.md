## What Lovable manages

Rules outside this block are the project's own. Change the pieces below in
Lovable, not by hand. With the [Lovable MCP](https://mcp.lovable.dev)
connected, `send_message` asks Lovable to do it; otherwise ask the user to
use the editor.

- **Database.** Do not add or edit `supabase/migrations/` or `drizzle/`.
  Ask Lovable to change the schema.
- **Generated files.** Do not edit a file whose header says it is automatically
  generated.
- **AI gateway.** Keep model calls on Lovable's gateway, and keep
  `LOVABLE_API_KEY` out of browser code.
- **Connectors.** Lovable provides native connectors. `list_connectors` shows
  which are enabled; `add_connector` only returns the dashboard link. When a
  connector is enabled, calls go through the connector gateway and need
  `LOVABLE_API_KEY`. When Lovable does not provide one, users can bring their
  own key and store it in Secrets.
- **Secrets.** Lovable manages them. Do not put secret values in the repo.

## Project rules

- Store pages share one shell in `src/routes/__root.tsx` (header, footer, cart sheet, cookie banner); add new pages as routes, not new layouts. Why: every page needs the same cart and consent UI.
- Order totals are always recomputed server-side from the `products` table via `computeOrderTotals` in `src/lib/pricing.ts`; never trust browser prices. Why: prevents price tampering.
- Customers, orders and order_items have RLS on with no public policies; only server functions/routes touch them through the admin client. Why: buyers check out without accounts.
- Payment status comes only from re-fetching the payment from Mercado Pago (`src/lib/mercadopago.server.ts`), both in the webhook and on the order page. Why: webhook bodies are unauthenticated.
- The per-order secret code is generated by a database trigger when an order becomes paid and is shown only for paid orders. Why: the code must not leak before payment.
- Consent is read only through `src/lib/consent.ts`; the defaults script in `src/lib/consent-defaults.ts` must stay the first head script. Why: tags must see consent defaults before loading.
